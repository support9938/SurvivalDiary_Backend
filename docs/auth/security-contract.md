# 인증 및 토큰 보안 계약

이 문서는 Flutter 앱, React 웹, Spring Boot API가 공유하는 인증 계약의 기준이다.
구현이 문서와 다르면 인증 구현과 이 문서를 같은 PR에서 함께 변경한다.

## 1. 책임 경계

- Spring Security는 보호 API 요청의 액세스 토큰을 검증하고 인증 사용자와 권한을 설정한다.
- `AuthController`와 `AuthService`는 회원가입, 로그인, 토큰 재발급, 로그아웃을 처리한다.
- 카카오와 네이버 공식 인증 서버는 SNS 사용자의 신원을 확인한다.
- 클라이언트가 전달한 이메일, 닉네임, SNS 사용자 ID는 신뢰하지 않는다. 백엔드가 공급자 서버에서 확인한 값만 사용한다.

## 2. 토큰 정책

| 항목 | 정책 |
|---|---|
| 액세스 토큰 | JWT, 30분, 보호 API의 `Authorization: Bearer` 헤더에만 사용 |
| 리프레시 토큰 | 14일, 재발급 전용, 일반 API 인증에 사용 금지 |
| 서버 저장 | 리프레시 토큰 원문을 저장하지 않고 SHA-256 해시만 저장 |
| 재발급 | 사용할 때마다 기존 토큰을 폐기하고 새 토큰으로 회전 |
| 재사용 | 이미 폐기되거나 교체된 토큰이 다시 제출되면 해당 토큰 계열을 폐기 |
| 로그아웃 | 현재 세션의 리프레시 토큰 폐기 |
| 전체 로그아웃 | 사용자의 모든 리프레시 토큰 폐기 |

JWT에는 비밀번호, 이메일, 전화번호 등 개인정보를 넣지 않는다. 액세스 토큰에는 사용자 ID,
역할, 토큰 종류, 발급·만료 시각과 토큰 식별자만 포함한다.

## 3. 클라이언트별 전달 방식

### Flutter 앱

- 액세스 토큰과 리프레시 토큰을 OS 보안 저장소에 저장한다.
- API 요청마다 액세스 토큰을 `Authorization` 헤더로 보낸다.
- 액세스 토큰 만료로 401을 받으면 한 번만 재발급하고 원래 요청을 한 번 재시도한다.
- 여러 요청이 동시에 401을 받아도 재발급 요청은 하나만 실행한다.

### React 웹

- 액세스 토큰은 메모리에만 보관한다.
- 리프레시 토큰은 `HttpOnly; Secure; SameSite=Lax` 쿠키로만 전달한다.
- 리프레시 토큰을 localStorage, sessionStorage 또는 JavaScript가 읽을 수 있는 쿠키에 저장하지 않는다.
- 쿠키 기반 인증 API는 허용된 Origin, CSRF 토큰과 CORS credentials를 함께 검증한다.

## 4. API 계약

기존 경로는 호환성을 위해 유지하며 신규 클라이언트는 아래 경로를 사용한다.

| 메서드 | 경로 | 인증 | 설명 |
|---|---|---|---|
| POST | `/api/auth/signup` | 공개 | 이메일 회원가입 |
| POST | `/api/auth/login` | 공개 | 앱 이메일 로그인 |
| POST | `/api/auth/token/refresh` | 리프레시 토큰 | 앱 토큰 회전 |
| POST | `/api/auth/logout` | 리프레시 토큰 | 앱 현재 세션 로그아웃 |
| POST | `/api/auth/logout-all` | 액세스 토큰 | 모든 세션 로그아웃 |
| POST | `/api/auth/social/kakao` | 공급자 토큰 | 앱 카카오 로그인 |
| POST | `/api/auth/social/naver` | 공급자 토큰 | 앱 네이버 로그인 |
| POST | `/api/auth/web/login` | 공개 | 웹 이메일 로그인 및 HttpOnly 쿠키 설정 |
| POST | `/api/auth/web/token/refresh` | 쿠키 + CSRF | 웹 액세스 토큰 재발급 |
| POST | `/api/auth/web/logout` | 쿠키 + CSRF | 웹 쿠키 및 서버 세션 폐기 |
| GET | `/api/auth/web/social/{provider}` | 공개 | 웹 SNS 인증 시작 |
| GET | `/api/auth/web/social/{provider}/callback` | state 검증 | 웹 SNS 콜백 |

성공과 실패 응답은 프로젝트 공통 `ApiResponse<T>` 형식을 사용한다. 로그인 실패는 계정 존재 여부를
노출하지 않도록 이메일 없음과 비밀번호 불일치를 모두 `U002`로 응답한다.

## 5. SNS 사용자 식별

SNS 계정은 이메일이 아니라 `(provider, provider_user_id)` 조합으로 식별하며 이 조합에 UNIQUE
제약조건을 둔다. 이메일이 같다는 이유만으로 계정을 자동 병합하지 않는다. 계정 연결과 해제는 로그인한
사용자가 재인증한 뒤 명시적으로 수행한다.

## 6. 보안 응답 기준

- 토큰 없음, 변조, 만료, 잘못된 토큰 종류: 401
- 인증은 됐지만 역할 또는 리소스 소유권 부족: 403
- 입력 검증 실패: 400
- 중복 이메일 또는 이미 연결된 SNS 계정: 409
- 인증 응답과 로그에는 비밀번호, JWT 원문, SNS 토큰, 쿠키 원문을 남기지 않는다.

## 7. 구현 순서

1. 리프레시 토큰 해시 저장, 식별자, 회전·폐기 상태를 Flyway로 추가한다.
2. 앱 재발급·로그아웃 API와 통합 테스트를 구현한다.
3. Flutter 보안 저장소, 자동 첨부, 단일 재발급 흐름을 구현한다.
4. 카카오 앱 로그인과 서버 검증을 구현한 뒤 네이버를 같은 계약으로 추가한다.
5. 웹 이메일 인증을 HttpOnly 쿠키와 CSRF 방어로 구현한다.
6. 웹 카카오·네이버 OAuth callback과 state 검증을 구현한다.
7. Rate Limit, 보안 헤더, 감사 로그와 탈퇴·전체 로그아웃을 검증한다.
